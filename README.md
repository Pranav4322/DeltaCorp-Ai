# Autonomous AI Creator — Full Stack

Built for the **ABTalks Vibe Code Hackathon**. See [`PROMPTS.md`](./PROMPTS.md)
for the AI usage log.

## Hackathon API compliance

The two endpoints the evaluator calls are implemented exactly to spec in
`backend/src/server.js`:

| Endpoint | Behavior |
|---|---|
| `POST /api/agent/init` | Called once. Body: `{ persona: { name, domain } }`. Returns `{ agentId }`. Immediately starts the autonomous scheduler — no further calls needed for the agent to keep working. |
| `GET /api/agent/feed?agentId=...` | Read-only, side-effect free (never triggers publishing itself). Returns `{ posts: [...] }`, newest first, each post with a unique `id`, ISO 8601 UTC `createdAt`, `text`, `rationale`, and `sources`. Returns `{ posts: [] }` before anything has published. Previously returned posts are never removed. |

Everything published after `init` is generated by the background pipeline
(`Scout → Curator → Writer → Critic`, plus an independent `Auditor` cycle
that later confirms or corrects earlier claims) on its own jittered
schedule — the evaluator polling `/feed` never has to prompt it again. Full
pipeline details are in `backend/README.md`.

Two separate, independently deployable folders:

```
autonomous-ai-creator/
├── backend/     Express + SQLite API (the persona pipeline)
└── frontend/    Static Tailwind CSS UI (no build step)
```

## Run both together (simplest)

```bash
cd backend
cp .env.example .env      # add your ANTHROPIC_API_KEY
npm install
npm start                 # -> http://localhost:3000
```

`backend/src/server.js` also serves the sibling `frontend/` folder as
static files, so visiting `http://localhost:3000` gives you the whole app
on one port.

## Run them separately

The frontend is a plain `index.html` + `app.js` (Tailwind via CDN, no
bundler) — open `frontend/index.html` directly in a browser, or host it
anywhere (Netlify, Vercel, S3, nginx, `npx serve frontend`, etc). On first
load it will ask you to initialize a persona; click the **⚙ settings**
icon in the topbar to point it at your backend's URL if it isn't running
on the same origin (e.g. `http://localhost:3000`, or wherever you deploy
`backend/`).

## What's inside

- **backend/** — unchanged pipeline logic (Scout → Curator → Writer →
  Critic → Auditor), SQLite storage, and the `/api/agent/*` REST API. See
  `backend/README.md` for the full endpoint reference and data model.
- **frontend/** — four themed views wired to the live API, styled with
  Tailwind CSS:
  - **Dispatch** — the post feed (posts, confirmations, corrections, inline claim status)
  - **Signal Room** — live pipeline stage indicators, recent feed, declined topics, accuracy gauge, raw activity log
  - **Ledger** — tabular published entries, claims & verdicts, confirmed/corrected/open balance
  - **Integrity** — integrity score, a trajectory chart built from resolved claims, and the resolution log

  Use the **force tick** / **force audit** buttons in the topbar during a
  demo to trigger a cycle immediately instead of waiting for the real
  jittered schedule.

## LLM provider fallback

`backend/src/llm.js` supports three providers — **Anthropic, Gemini, and
OpenRouter** — tried in that order on every call. Set any one of
`ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY` in `.env` (or
your host's env vars) to use that provider; set more than one and it
automatically falls through to the next if a call fails (bad key, rate
limit, transient outage), with no code changes needed. See
`backend/.env.example` for the full list of provider/model env vars.

**Never commit real API keys.** `.env` is already gitignored — keep keys
there locally, and enter them directly into your host's dashboard (e.g.
Render's env var UI) when deploying. A public hackathon repo with a key
committed to it, even in an old commit, is a leaked key.

## Deploying for submission (live demo URL)

This backend is a **long-running process** (a `node-cron` schedule keeps
ticking in the background, and it keeps a local SQLite file open) — not a
stateless function. Deploy it somewhere that runs it continuously, not on
Vercel/Netlify serverless functions, which would reset the scheduler and
the database on every request.

**Render (recommended, one click):**
1. Push this repo to GitHub (public).
2. In Render: **New → Blueprint**, point it at the repo — it picks up
   [`render.yaml`](./render.yaml) automatically (`rootDir: backend`, a
   persistent disk for the SQLite file, health check on `/health`).
3. Fill in whichever `_API_KEY` value(s) you have when prompted — you only
   need one, but if you set more than one they act as automatic fallbacks
   for each other (see below). Deploy.
4. Your live demo URL is the Render service URL — `POST /api/agent/init`
   and `GET /api/agent/feed` work at `<that-url>/api/agent/...`, and the
   Tailwind frontend is served at the root of the same URL.

**Railway / Fly.io / a plain VM** work the same way: `cd backend`, install,
`npm start`, expose the port, set `ANTHROPIC_API_KEY` (and optionally
`DATA_DIR` to a mounted volume so the SQLite file survives restarts).

**Frontend only, elsewhere:** since `frontend/` is static (Tailwind via
CDN, no build step), it can also be hosted separately on Netlify/Vercel and
pointed at the backend's URL via the **⚙ settings** modal — but the API
itself must live on a persistent host as above.
